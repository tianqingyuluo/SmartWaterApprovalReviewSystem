# SmartWater V1 PRD 初稿

> 状态：初稿，待评审。本文基于本任务 `prd.md` 中已确认的讨论决策整理，不代表最终实施计划。

## 1. 背景与目标

SmartWater V1 在 MVP 基础上继续建设取水许可智能初审系统。V1 的核心目标不是重做基础架构，而是围绕课程四个检查点补齐知识库、MCP Server、LangChain Agent、Java-Python 集成、账号权限、补正闭环、报告导出和答辩交付能力。

V1 采用“课程检查点父任务 + 系统模块子任务”的混合组织方式：

* 对外汇报按 CP1-CP4 课程检查点组织。
* 对内开发按 Java 后端、Python AI 服务、前端页面、文档测试演示四类任务分派。
* 每个检查点尽量拆成四个人可并行承担的任务包。

## 2. 用户与角色

V1 包含三类角色：

* 申请人：自助注册、登录、提交申请材料、查看自己的申请、查看补正意见、补传材料。
* 审批人员：登录后查看待办、查看 AI 初审结果、执行通过初审、退回补正、转人工复核、填写备注。
* 管理员：管理用户、创建审批人员和管理员账号、分配角色、禁用账号、查看全量任务概览。

权限规则：

* 申请人只看自己的申请。
* 审批人员看所有待办。
* 管理员看全部申请和用户。
* V1 不做部门、区域、任务派单和复杂审批流。

## 3. V1 范围

### 3.1 产品能力

V1 包含：

* 登录、注册、Sa-Token 鉴权、Redis 登录态。
* 申请人、审批人员、管理员角色和动态菜单。
* 我的申请、审批待办、角色工作台、用户管理。
* 固定主槽位上传：申请书、营业执照、身份证。
* 自由附件区，用于补充材料上传和扩展演示。
* 退回补正、材料版本、AI 复审、操作日志。
* 材料、字段、问题三类版本差异。
* AI 初审辅助结论、结构化问题列表、依据片段、修改建议、人工复核提示。
* Word 初审报告导出。

### 3.2 课程 CP2 能力

V1 包含：

* 课程指定参考资料 ingest。
* Word、PDF、图片解析。
* ChromaDB 持久化向量库。
* 外部 API Embedding。
* MCP Server 独立启动和工具演示。
* `knowledge_search` 与 `check_completeness` 工具。

CP2 主线知识库资料：

* `取水许可办理需资料及流程.docx`
* `填报说明.docx`
* `国民经济分类国标.pdf`
* `申请书.docx`
* `营业执照.jpg`
* `身份证.jpg`
* `驾驶证.png` 作为负向样例

### 3.3 课程 CP3 能力

V1 包含：

* FastAPI AI 服务接口。
* Java 异步创建 AI 审查任务。
* Python 下载材料、解析/OCR、字段抽取、RAG 检索、规则检查、Agent 汇总。
* Python 回调 Java 写回审查结果。
* Java 主动查询 Python 任务状态作为兜底。
* LangChain Agent 生成 AI 初审辅助建议。
* 同一测试用例多次运行时结构化结论稳定。

### 3.4 CP4 答辩交付

V1 包含：

* README、API 说明、部署说明、运行截图和演示脚本。
* 四个检查点验收证据。
* Word 初审报告导出示例。
* RustFS、ChromaDB、MCP Server、FastAPI、Java 后端、前端联调演示。

## 4. 非目标

V1 不做：

* 完整正式审批流。
* 部门/区域分派。
* 在线结构化申请表填写。
* 全量材料槽位固化。
* 自动材料分类。
* 完整规则引擎或后台规则管理。
* 知识库后台管理页面。
* AI 任务监控后台。
* 对象存储文件管理后台。
* PDF 导出。
* 全文级、OCR 文本级、PDF 页面级版本 diff。

## 5. 核心业务流程

### 5.1 申请提交

1. 申请人注册并登录。
2. 申请人上传申请书、营业执照、身份证和可选附件。
3. Java 校验扩展名、MIME、大小和材料槽位。
4. Java 将文件写入 MVP 已搭建的 RustFS S3 兼容对象存储。
5. Java 创建申请和材料版本记录。
6. Java 生成材料短期预签名 URL，调用 Python FastAPI 创建 AI 审查任务。

### 5.2 AI 初审

1. Python FastAPI 返回 `aiTaskId`。
2. Python 后台任务下载材料。
3. Python 按格式解析：`.doc` 通过 LibreOffice 转 `.docx`，`.docx` 用 `python-docx`，`.pdf` 用 PyMuPDF，图片走 GLM OCR。
4. Python 混合抽取字段：模板/规则优先，LLM 按 JSON schema 兜底。
5. Python 调用结构化规则检查。
6. Python 调用知识库检索，获取依据片段。
7. LangChain Agent 汇总规则结果和依据，生成 AI 初审辅助建议。
8. Python 回调 Java 写回结果；Java 幂等保存。

### 5.3 审批人员处理

1. 审批人员进入待办列表。
2. 审批人员查看申请详情、系统识别信息、AI 初审结果、问题列表和依据片段。
3. 审批人员选择通过初审、退回补正或转人工复核。
4. 系统记录操作日志。

### 5.4 补正复审

1. 审批人员退回补正并填写意见。
2. 申请人查看补正意见。
3. 申请人补传材料，形成新材料版本，不覆盖旧版本。
4. 系统触发新一轮 AI 复审。
5. 页面展示材料、字段、问题三类差异。

### 5.5 报告导出

1. 审批人员或管理员在申请详情页导出 Word 初审报告。
2. Java 基于固定模板和数据库中的审查快照生成 `.docx`。
3. 报告明确 AI 结论不构成正式审批决定。

## 6. 核心数据对象

V1 需要覆盖以下概念对象：

* 用户、角色、权限。
* 申请。
* 材料。
* 材料版本。
* AI 审查任务。
* AI 审查结果主表。
* AI 问题明细表。
* 关键字段抽取快照。
* 审批操作日志。
* 补正意见。
* 报告导出记录。

AI 审查结果采用“主表 + 问题明细表 + 原始 JSON 快照”：

* 主表保存任务关联、材料版本关联、AI 任务状态、辅助结论、整体说明、人工复核提示、生成时间和原始 JSON。
* 问题明细保存 `code`、严重程度、材料槽位、字段、问题说明、依据片段、修改建议、是否需人工复核和排序。

## 7. 验收标准

V1 完成时应满足：

* CP1：能证明 MVP 基础架构、Java Web、前端页面、Python 服务、数据库、Git 协作已经具备。
* CP2：能重复 ingest 课程资料，输出文档数、chunk 数、向量条目数；MCP Server 可独立启动并演示 `knowledge_search`、`check_completeness`。
* CP3：能从前端提交材料，经 Java 调 Python，Python 完成 AI 初审并回写 Java，前端展示结构化结论。
* CP3：同一测试用例多次运行时，辅助结论、问题 code、材料/字段、严重程度保持一致。
* CP4：能完成角色化端到端演示、补正复审演示、Word 报告导出演示和部署文档说明。
