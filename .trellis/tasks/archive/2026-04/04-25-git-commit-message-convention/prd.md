# 规范 Git 提交消息格式

## Goal

新增团队提交消息规范，要求每次 Git 提交使用英文类型前缀加中文说明，提升历史可读性与团队协作一致性；同时评估已推送历史提交是否适合改写。

## What I Already Know

* 用户要求新增 spec：每次 git 提交需要“英文前缀 + 中文 comment”。
* 用户询问之前的提交是否能改成该格式。
* 当前项目使用 Trellis 任务与团队协作 spec 管理开发纪律。
* `mvp/smartwater` 已推送给团队，已有合并 PR 与多名开发者分工记录。

## Requirements

* 新增或更新 `.trellis/spec/` 中的团队提交规范。
* 明确提交消息格式、示例、允许的英文前缀。
* 明确不推荐改写已推送共享分支历史，除非团队全员确认并协调强推。
* 如需调整最近未共享提交，可使用 amend/rebase；共享提交优先通过新提交补正规范。

## Acceptance Criteria

* [x] spec 中明确 commit message 格式。
* [x] spec 中包含正确/错误示例。
* [x] spec 中说明历史提交改写风险与决策规则。
* [x] 本次变更自身使用新格式提交。

## Definition of Done

* 规范文件已更新并可被后续开发者引用。
* 已检查近期历史提交，给出是否改写的建议。
* 工作区干净或明确说明剩余变更。

## Out of Scope

* 不强制安装 git hook。
* 不自动重写已推送远端历史，除非用户明确二次确认。
