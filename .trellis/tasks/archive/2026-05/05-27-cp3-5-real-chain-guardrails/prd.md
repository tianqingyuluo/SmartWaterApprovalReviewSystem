# CP3.5-A 全真实链路护栏与失败复盘

## Scope

把 CP3 失败原因、CP3.5 真实链路路线、验收证据模板和禁止演示兜底的规则固化下来。这个任务先于所有实现任务完成，避免后续又滑回“为了演示而做玩具”的路线。

## Problem

CP3 不是单点功能没做完，而是验收路线错误：系统用 mock/stub、规则兜底、轮询证明和前端占位拼出可讲述的演示，却没有真实跑通 OCR、LLM、MCP、对象存储、Java-Python 调度和前端证据核验。CP3.5 必须先定义清楚什么叫真实通过。

## Deliverables

- CP3 失败复盘文档，明确此前哪些证据只证明测试或演示，不证明生产级链路。
- CP3.5 验收清单，覆盖真实账号、真实材料、真实对象存储、真实 OCR、真实 LLM、真实 MCP、真实 Java-Python 调度和真实前端展示。
- 禁止演示兜底规则：
  - 不用 mock/stub 结果当最终验收。
  - 不用规则兜底替代 Agent 智能结论。
  - 外部智能依赖失败时必须明确失败/阻塞/待重试。
- CP3.5 子任务依赖图和完成顺序。
- `docs/readable/**` 的后续证据模板，准备记录运行步骤、截图/日志、账号提交证据和复跑结果。

## Acceptance Criteria

- CP3.5 父任务 PRD 和本任务 PRD 均写明 CP3 失败根因。
- 后续子任务的 `implement.jsonl` / `check.jsonl` 都引用失败复盘或父任务 PRD。
- 验收模板明确区分单元测试 mock、集成测试、真实联机 E2E。
- 明确写入“失败即失败，不伪造智能结论”的状态规则。
- Git 提交证据要求覆盖到账号维度，不把单一账号提交数冒充全组贡献。

## Non-Goals

- 不实现业务代码。
- 不补 CP4 报告导出、补正版本差异或部署答辩材料。
- 不讨论“更好看的演示包装”；本任务只收紧真实链路和验收定义。

## Dependencies

- 无。该任务是 CP3.5 起点。
