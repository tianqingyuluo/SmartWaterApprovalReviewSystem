# CP3-E 最小 RBAC 与任务可见性

## Scope

为 CP3 真实流程补齐最小身份边界：申请人提交自己的涉水申请，审批人员查看待办并处理，管理员具备种子账号或基础系统角色。该任务只做让真实流程可信运行所需的 RBAC，不展开完整后台管理。

## Deliverables

- Java 后端最小账号、角色、登录和当前用户接口。
- 申请人、审批人员、管理员三类角色的种子数据或初始化方案。
- 后端接口按登录身份限制任务可见性：
  - 申请人只能查看自己提交的申请和结果。
  - 审批人员可查看 AI 初审完成或待人工处理的任务。
  - 管理员可查看全部任务，用于演示和排障。
- 前端登录态接入真实后端 token，不再只靠本地假登录表达权限。
- 前端菜单和默认页面按角色显示：申请人申请/我的申请，审批人员待办，管理员基础入口。

## Non-Goals

- 不做完整管理员用户管理页面。
- 不做部门、区域、任务派单或复杂组织架构。
- 不做补正后的重传、版本差异、报告导出。
- 不把前端动态菜单当作唯一权限控制；后端必须强制校验。

## Acceptance Criteria

- 未登录访问业务 API 被拒绝。
- 申请人 A 不能查看申请人 B 的任务和结果。
- 审批人员可以看到审批待办，不能伪装成申请人提交归属。
- 管理员可查看全部任务列表。
- 前端登录后按角色进入对应工作入口。
- Java 单测或集成测试覆盖登录、角色和任务可见性关键路径。

## Dependencies

- 已归档：`v1-cp3-java-ai-task-callback-results`
- 后续依赖：`v1-cp3-reviewer-actions-applicant-result`

## CP4 Boundary

CP4 可在本任务基础上增加管理员用户管理、角色分配页面、补正提醒和更完整工作台。本任务只交付 CP3 真实闭环所需的最低身份和授权能力。
