# Codex 子代理使用规范

> 适用于 Codex 主会话在考虑调用 `spawn_agent` 前的判断。

## 核心规则

本项目禁用 Codex 子代理。主会话不得调用 `spawn_agent`、`followup_task`、`wait_agent` 或相关子代理调度工具来完成本仓库工作。

即使 Trellis 通用流程、历史任务、旧提示或某些平台模板提到 `trellis-implement`、`trellis-check`、`trellis-research` 子代理，也按本项目配置 `.trellis/config.yaml` 中的 `codex.dispatch_mode: inline` 执行：主会话直接读取规范、实现、检查、测试、修复、提交和归档。

历史 Trellis 模板中的“按需启动子代理”规则在本项目不适用。本项目不按任务大小、复杂度或并行度例外启用子代理。

子代理会引入调度、等待、同步和结果核验成本；本项目统一用主会话直接推进，必要时只并行普通命令。

## 禁用规则

- 当前项目不再评估“是否值得启动子代理”；答案一律为不启动。
- 正式 Trellis 任务流也走 inline：主会话加载 `trellis-before-dev`、直接实现、加载 `trellis-check`、运行测试并修复。
- 研究产物仍然必须写入 `{TASK_DIR}/research/*.md`，但由主会话直接完成。
- 质量检查仍然必须执行，但由主会话加载 `trellis-check` skill 并直接运行。

## 不应启动子代理的情况

- 本项目的所有情况。
- 简单问答、路径定位、少量文件只读检索。
- 单文件或少量配置的直接修改。
- 当前上下文不足以给子代理一个清晰、可验收的任务。
- 启动子代理只是为了“看起来更稳”，但实际会增加等待和同步成本。

## 正确做法

- 所有任务由主会话直接完成。
- 需要并行命令时，只使用 `multi_tool_use.parallel` 并行普通 shell 读取/测试命令，不启动子代理。
- 如果遇到旧工作流提示要求派发子代理，优先遵守本项目禁用规则，改为主会话加载对应 skill 并直接执行。
