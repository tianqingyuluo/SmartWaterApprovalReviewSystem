# 前端页面与角色可见性

## 登录态

前端现在使用 Java 后端真实登录接口：

- `POST /api/auth/login`
- `GET /api/auth/me`

登录成功后，前端在 `localStorage` 保存 token 和当前用户信息。请求层会把 token 写入：

```text
Authorization: Bearer <token>
```

如果后端返回业务码 `401`，前端会清理 token 和用户信息，并跳转回登录页。

## 角色入口

当前角色入口保持 CP3 最小范围：

- 申请人：查看申请列表、提交新申请、查看自己的申请人结果。
- 审批人员：查看审核待办和 AI 初评结果，不显示新建申请入口。
- 管理员：可用于演示和排障，保留更多入口。

前端菜单只是用户体验层，真正权限由 Java 后端校验。

## 结果可见性

申请人结果页只调用申请人结果接口，不读取审批人员结果：

- `GET /api/task/{taskId}/result/applicant`

申请人页面可显示缺失材料、可见问题和基础建议，但不能显示 OCR 字段快照、风险提示、AI 草拟审批意见等审批人员信息。

审批人员或管理员查看审核结果时调用：

- `GET /api/task/{taskId}/result/reviewer`

审批人员视图可以显示字段抽取、置信度、风险提示、依据引用和草拟意见。

## 初审处理结果与动作

CP3-F 后端已在申请人结果、审批人员结果、任务状态和任务列表中返回初审处理快照。CP3-C 前端已按角色接入这些字段：

- 申请人侧可以显示初审处理结果、审批人员备注和处理时间。
- 审批人员侧可以显示当前处理结果和操作日志。
- 审批人员/管理员可以在审核详情页提交通过初审、退回补正、转人工复核三类动作。
- 任务列表显示初审处理状态和审批备注摘要，便于审批人员查看待办处理进度。
- AI 结论仍必须标注为辅助建议，不能把 `COMPLETED` 或初审动作误写成正式行政许可决定。

当前处理状态含义：

| 处理状态 | 申请人展示语义 | 审批人员展示语义 |
|---|---|---|
| `INITIAL_REVIEW_PASSED` | 已通过初审 | 已通过初审 |
| `CORRECTION_REQUIRED` | 需要补正材料，可补传 | 已退回补正 |
| `MANUAL_REVIEW_REQUIRED` | 已转人工复核 | 已转人工复核 |

## 申请人办理提醒栏

CP4 之后，申请人列表页和申请人结果页都增加了办理提醒栏，用于把初审处理动作更直观地展示给申请人。

提醒栏只使用申请人可见字段：

- `handlingStatus`
- `handlingStatusLabel`
- `reviewerRemark`
- `reviewerActionAt`

展示规则：

- `CORRECTION_REQUIRED`：显示退回补正提示，并在结果页提供“补传材料”跳转。
- `INITIAL_REVIEW_PASSED`：显示通过初审提示，提醒申请人继续关注后续办理通知。
- `MANUAL_REVIEW_REQUIRED`：显示已转人工复核提示，说明申请单仍在处理链路中。

列表页显示汇总提醒和若干条最近办理记录，结果页在任务信息上方显示单条醒目提醒。

CP4-C 后，申请人结果页在 `handlingStatus=CORRECTION_REQUIRED` 时显示“补正材料补传”面板：

- 面板只在申请人投影展示，审批人员/管理员结果投影不展示补传入口。
- 面板复用三类固定材料槽位：取水许可申请书、营业执照、身份证。
- 前端仅做扩展名预检查，最终校验和权限由 Java 后端负责。
- 补传成功后页面重新查询任务状态和申请人结果；后端清空初审处理快照后，补传面板会自动隐藏，任务进入重新处理状态。

材料版本差异视图和报告导出仍属于后续 CP4 收口，不在当前页面提前展示不可用入口。

前端实现边界：

- `src/api/task.ts` 负责把后端 DTO 转成页面 view model，包括申请人结果、审批人员结果和动作日志。
- 申请人结果页只由申请人 projection 和任务状态快照生成，不读取审批人员结果 DTO。
- 本地保存的用户资料必须通过运行时校验；畸形角色不能被用来决定页面投影。
