## 1. 定位

CP3.5-A 是 CP3 修复主线的入口任务。它不实现业务代码，而是先固定失败复盘、真实链路验收口径、禁止演示兜底规则和后续证据模板，防止后续子任务再次把局部测试或页面演示当成生产级初审 Agent。

后续实现任务必须同时阅读：

- `.trellis/tasks/05-26-cp3-5-agent/prd.md`
- `.trellis/tasks/05-26-cp3-5-agent/research/cp3-failure-root-cause.md`
- 本文档

## 2. CP3 失败复盘

CP3 的问题不是单个接口没有完成，而是验收路线错误。已有证据证明了一部分自动化测试和局部集成，但没有证明真实智能链路可以跑通。

| 旧证据或做法 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| Java H2/test profile 回归 | DTO、状态流转、回写持久化的部分逻辑正确 | 真实 MySQL、RustFS、Java 主动调度 Python、真实材料下载 |
| Python mock/stub 测试 | Orchestrator、adapter、回写代码在受控输入下可运行 | 真实 OCR、真实 LLM、真实 MCP、真实知识库调用 |
| Worker 轮询链路 | Python 可以按旧 Worker 入口领取并回写结果 | 前端提交后 Java 主动调用 Python FastAPI 的生产链路 |
| 前端结果页展示抽取字段 | reviewer/applicant 投影和页面渲染可用 | 审批人员能对照原始 PDF/图片材料核验 AI 结论 |
| 规则兜底与人工复核提示 | 系统能给出可解释的保守提示 | Agent、OCR、MCP、RAG 或 LLM 真实成功 |
| GLM OCR 裸 base64 请求 | 暴露了真实联机失败 | 不能作为 OCR 成功证据 |

因此，CP3.5 不能再用“测试通过”“页面能看”“规则能兜底”来替代真实联机验收。

## 3. 证据分层

后续 PR 和答辩证据必须明确区分三层证据。

| 证据层级 | 允许用途 | 不允许用途 |
| --- | --- | --- |
| 单元测试 mock | 证明局部逻辑、错误映射、DTO 序列化、adapter 分支 | 不能写成真实 OCR/LLM/MCP 成功 |
| 受控集成测试 | 证明 Java/Python/前端契约和状态流转 | 不能替代真实中间件和外部 AI 联机 |
| 真实联机 E2E | CP3.5 最终验收和答辩主证据 | 失败时不能伪造结论或静态截图 |

最终 CP3.5 验收必须包含真实账号、真实材料、真实对象存储、真实 OCR、真实 LLM、真实 MCP Client 调用、真实 Java-Python 调度和真实前端展示。

## 4. 失败即失败规则

CP3.5 的状态规则是：关键智能依赖失败时，系统必须明确失败、阻塞或待重试，不能生成看似成功的智能审查结论。

关键依赖包括：

- 对象存储上传、下载和权限校验。
- Java 主动调度 Python FastAPI。
- Python 解析 PDF/DOCX、图片和扫描件 OCR。
- MCP Client 发现和调用 `knowledge_search`、`check_completeness` 等工具。
- LLM Agent 结构化推理和 schema 校验。
- Python 回写 Java 结果持久化。

执行规则：

- 外部 OCR、LLM、MCP 或 Java 回写在有界重试后仍失败时，任务进入 `FAILED`、`RETRYABLE_FAILED` 或等价阻塞态；当前枚举尚未扩展时至少使用 `FAILED` 并记录可重试原因。
- 规则检查可以保留为诊断信息，但不得被展示或记录为“AI 审查成功”。
- 缺材料、格式不支持、低置信度 OCR 等业务问题要转成明确 issue；不要用空文本、mock 文本或硬编码结论填充。
- 前端必须展示真实状态和失败原因摘要，不用静态截图、隐藏按钮、硬编码样例或“处理中占位”冒充通过。
- 日志和文档只记录脱敏摘要、依赖名、失败分类、trace/request ID 和是否可重试，不记录 API key、Worker token、`storageKey`、身份证全文、营业执照全文或完整 prompt。

## 5. CP3.5 验收清单

| 验收项 | 最低证据要求 | 负责人任务 |
| --- | --- | --- |
| 真实账号 | 申请人、审批人员、管理员账号登录截图或日志；Git 提交证据按团队账号分别整理 | CP3.5-F |
| 真实材料 | 至少三组样例：基本合规、缺材料、内容明显有问题；记录文件名、类型、用途 | CP3.5-C / CP3.5-F |
| 真实对象存储 | Java 上传到 RustFS，Python 通过受控接口下载；证据中脱敏 `storageKey` | CP3.5-B / CP3.5-G |
| Java 主动调度 Python | 前端提交后 Java 调用 Python FastAPI，日志含同一 `taskId` 或 trace ID | CP3.5-B |
| 真实 OCR/解析 | 图片走 GLM OCR 且返回 200；PDF/DOCX 能提取文本或表格；失败状态可见 | CP3.5-H / CP3.5-C |
| 真实 MCP Client | Agent 通过 MCP Client 发现并调用工具；证据包含工具名、输入摘要、输出摘要、状态 | CP3.5-D |
| 真实 LLM Agent | 真实模型返回结构化结论、问题、依据、建议和模型元数据 | CP3.5-E |
| 前端证据核验 | 审批人员可同时看到原始材料预览、OCR/抽取字段、AI 结论、问题、依据和建议 | CP3.5-G / CP3.5-F |
| 失败注入 | 分别关闭 OCR、LLM、MCP 或 Python 服务，系统不生成假成功结论 | CP3.5-B / CP3.5-D / CP3.5-E / CP3.5-F |
| 稳定性复跑 | 同一材料复跑 3 次，关键结论、问题编码、严重级别和依据稳定 | CP3.5-E / CP3.5-F |

## 6. 子任务顺序

```text
CP3.5-A 护栏先行

CP3.5-B Java 主动调度 Python
CP3.5-H GLM OCR data URI 修复
CP3.5-G 材料安全预览

CP3.5-C 生产级文档解析与 OCR
  -> CP3.5-D MCP Client 真实工具调用
  -> CP3.5-E 智能合规审查与结构化结论
  -> CP3.5-F 真实端到端验收与答辩证据
```

执行纪律：

- `B` 和 `H` 是技术前置，分别决定主链路能否调度、真实 OCR 能否成功。
- `G` 可以并行准备前端和安全预览接口，但不能用占位区域代替真实材料预览。
- `C/D/E` 必须基于真实输入和真实工具结果推进，不能先做规则演示再包装成 Agent。
- `F` 最后收口，只接收来自 `B/C/D/E/G/H` 的真实运行证据。
